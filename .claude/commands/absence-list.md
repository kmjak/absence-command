欠席になっている日付を一覧で出力するコマンドです。

学生ポータルの「出欠確認」ページが内部で使っている API エンドポイント
（`/PortalManagementWeb/public/attendancedetail/search`）を `scripts/attendance.sh` 経由で直接叩き、
欠席（出欠区分=2）のデータを構造化 JSON で取得します。HTMLのスクレイピングは行いません。

---

## 実行

`$ARGUMENTS` を範囲指定として `scripts/absence_list.sh` に渡して実行してください。
**引数が無い場合は既定（`fy` = 今年度・4/1以降）** で実行します。

```bash
./scripts/absence_list.sh <RANGE>
```

`absence_list.sh` が内部で `attendance.sh` を呼び（自動ログイン＋全ページ取得）、
指定範囲で絞り込み、日付ごとに集約して整形表示します。出力をそのままユーザーに提示してください。

### 指定できる範囲（RANGE）

| 指定 | 意味 |
|------|------|
| （なし） / `fy` | 今年度（4/1以降）※デフォルト |
| `1y` | 直近1年 |
| `6m` | 直近6ヶ月 |
| `3m` | 直近3ヶ月 |
| `1m` | 直近1ヶ月 |
| `all` | 全期間 |
| `YYYYMMDD` | 指定日以降 |

出力例:

```
欠席一覧（今年度（2026/04以降） / 全 37 コマ・17 日分）

   1) 2026-07-22 (水) … ネットワーク演習Ⅱ（2コマ）
   2) 2026-07-18 (土) … 設計・開発（2コマ）
  ...
```

エラー（セッション切れ等）で有効な JSON が返らない場合は、以下でセッションを取り直してから
`absence_list.sh` を1度だけ再実行してください（PHPSESSID は自動取得されるので、ユーザーに
ブラウザからコピーしてもらう必要はありません）。

```bash
./scripts/session.sh
```

`session.sh` も失敗する場合は、`.env` の URL / ログインID / パスワードの誤りが考えられるため、
`/absence setup` の実行を案内して終了してください。

## 日付を選んで公欠申請へ

一覧を提示したあと、続けて以下を聞いてください:

```
公欠を申請する日付を選んでください（番号 or YYYY-MM-DD / 複数はカンマ区切り / 不要なら Enter）:
```

- **Enter（空入力）** … 一覧の表示だけで終了してください。
- **番号 / 日付が入力された場合** … その日付を確定し、`.claude/commands/absence.md`（`/absence`）の
  手順を **Step 1 の日付として確定済みの状態から** 実行してください。
  日付を聞き直す必要はありません（Step 1 の質問はスキップ）。

該当する番号が一覧に無い場合は、その旨を伝えてもう一度選ばせてください。

### 複数の日付が指定された場合（重要）

**申請フォームは「1申請＝1日分」です。複数の日付を1つの申請にまとめて送ってはいけません。**
`run.sh` の DATE/PERIODS 枠（最大5組）は、**同じ1日の中の複数コマ**を並べるための枠であり、
別々の日を並べるための枠ではありません。

複数の日付（例: `1,3,5` や `2026-07-02,2026-07-18`）が指定された場合は、
**指定された日付を1つずつ、日付ごとに独立した申請として順番に処理してください。**

処理の進め方:

1. 指定された日付を古い順に並べ、「これから N 件を1件ずつ申請します」とユーザーに伝える。
2. 1件目の日付について `/absence` の **Step 1〜Step 7 を最後まで完了**させる
   （授業選択・理由・写真の確認・`run.sh` 実行・ログ保存まで）。
3. 1件目が完了したら、2件目の日付について同じく Step 1〜Step 7 を最初から実行する。
   以降、指定された全ての日付について同様に繰り返す。

守ること:

- **`run.sh` の実行は「1日につき1回」**。1回の `run.sh` に複数日の DATE を渡さないこと。
- 前の日付の申請（`run.sh` 実行とログ保存）が終わる前に、次の日付の処理を始めないこと。
- ログファイル（`logs/log/YYYY-MM-DD-<title>.md`）も**日付ごとに1ファイルずつ**作成すること。
- 理由・写真は日付ごとに聞き直すのが基本です。ただし1件目の入力後に
  「他の日も同じ理由・写真でよいですか？」と確認し、ユーザーが同じで良いと答えた場合は
  2件目以降の Step 4〜5 を省略して同じ値を使い回して構いません（それでも申請は日付ごとに別々に送ること）。
- 途中で失敗した日付があれば、そこで止めずに残りを処理し、最後に「成功した日付／失敗した日付」を
  まとめて報告してください。

全件終わったら、日付ごとの申請結果を一覧でまとめて報告してください。

## 補足

- 出欠区分そのものを変えて確認したい場合は `scripts/attendance.sh` を直接使えます
  （第1引数: `1:出席 2:欠席 3:遅刻 4:早退 5:公欠 6:理欠`、第2引数: 年度）。
  例: 公欠済みを確認 → `./scripts/attendance.sh 5`
- 同じ欠席データで範囲だけ変えて何度も見たいときは、一度取得した JSON を使い回せます。
  例: `./scripts/attendance.sh > /tmp/absence.json` 後に
  `ABSENCE_JSON=/tmp/absence.json ./scripts/absence_list.sh 1m`
